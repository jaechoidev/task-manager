# Findings: the scheduler and the API as a service (2026-11-25)

Every run so far began because somebody started a process in a terminal. This makes the scheduler and the API two launchd agents, so that labelling an issue is all it takes.

## Result

| | |
| --- | --- |
| Built | `factory service install`, `uninstall` and `status`. A watching scheduler that survives GitHub not answering |
| Tested with stand-ins | 127 unit tests and 55 scenarios. The watch scenario now takes GitHub away for three seconds |
| Run for real | Scratch agents under launchd, loaded for one login only and then removed. After that, the real install on this MacBook |
| Not run for real | A restart of the Mac. An issue run by the installed service. The Mac Studio |

## What the scratch run showed

Two agents with a suffix in their names, their property lists in a scratch folder, and a scratch factory home.

- **Both ran, and the API answered.** The scheduler listed both registered repositories, so `gh` works under launchd.
- **A killed scheduler came back.** 18 seconds after `kill -9`, with a new process id. The agents wait 30 seconds at most between starts.
- **No login went along.** The scheduler's environment held `PATH`, the factory home, `USER` and `HOME`. Every run before this was started from a shell inside a Claude Code session, where Claude takes that session's login. Under launchd it can't.
- **The machine's own logins answer there.** A one-off agent read all three plans: ChatGPT, Claude and GLM all answered within nine seconds.
- **It read Claude's 5-hour window at 100%.** That is this machine's own login, and the first reading of it. Until its reset the engine would have set Claude aside and gone to the next in each list.

## The install on this MacBook

`factory service install`, with no flags, from a shell with no `FACTORY_HOME`.

- Both agents are in `~/Library/LaunchAgents` and running.
- The API answers on `127.0.0.1:7878` for both repositories, and the app shows the scheduler with 0 of 3 places in use.
- The hand-started API had to be stopped first. Two can't listen on one address.
- Nothing carried the `today` label at the time, so nothing started.

## What had to change in the scheduler

A scheduler that runs for weeks meets things a twenty-minute run does not.

- **GitHub not answering ended it.** Listing the labelled issues failed, and the scheduler returned the error. Under launchd that restarts it, which leaves every issue at work without the scheduler that started it. What launchd does to those issues was not tried. With `--watch` it now says so once, keeps what it listed last, and says when GitHub answers again.
- **An issue another process holds was never looked at again.** It is now looked at again at the next round, and said only once.

## How it is put together

- **Two agents, not one.** The API has to stay up while the scheduler is restarted, and the other way round.
- **`KeepAlive` and `RunAtLoad`.** Started at login, started again whenever they stop.
- **The scheduler is marked as interactive work** for launchd, so that builds and simulators are not slowed as background work would be. The API is not.
- **The environment is written out.** Only `PATH` and, when set, `FACTORY_HOME`.
- **No daemon of our own.** The design doc has one process that runs the loop and serves the API. Here they stay two processes that meet in the database and the lock files, each kept alive by launchd.

## Open items

- **A restart of the Mac.** The agents are where launchd reads them at login. That was not tried.
- **Keychain after a restart.** The logins answered in this login session. Whether they do before anyone has unlocked the keychain is not known.
- **The agents run the build in the checkout.** `cargo build --release` replaces the program under a running service. A copy in a fixed place would be safer.
- **Logs only grow.** Nothing rotates `schedule.log` and `serve.log`.
- **Nothing tells you when an agent keeps dying.** `factory service status` says it is not running right now. It does not count restarts.
- **The API has no token on localhost.** Anything on this Mac can call it, and it can start runs. That was already so when started by hand. Now it is always there.
